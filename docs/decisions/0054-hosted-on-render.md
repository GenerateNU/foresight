# 0050. The backend is hosted on Render's free plan

**Status:** Accepted · **Date:** 2026-11-07

## Context
The backend only ran locally. The MVP needs a public URL that serves real
sign-ins, with Neon staying the database
([0027](0027-neon-postgres.md)). All the data is demo data and there is no
budget yet, so cost matters more than uptime for now.

## Decision
- **One Render web service, declared in `render.yaml`**, built from
  `backend/Dockerfile`. Render builds the last stage, so `prod` stays last.
- **The free plan.** It can be changed in one line when it stops being enough.
- **Migrations run when the container starts**, before uvicorn, using
  `DATABASE_URL_UNPOOLED`. The free plan has no pre-deploy step. A failed
  migration stops the server from starting, so the deploy fails and the previous
  version keeps serving.
- **The region is Virginia**, next to Neon in AWS US East. Render can't change a
  service's region afterwards.
- **Only backend changes that passed CI deploy** (`autoDeployTrigger:
  checksPass`, `buildFilter: backend/**`), because a deploy kills running jobs.
- **Secrets are entered in Render** (`sync: false`), never committed.
  `SESSION_SECRET` is generated by Render.
- **The cookie stays `SameSite=lax`.** `none` would let another site's form send
  the cookie with bodyless POSTs such as `/ingest/events`, and there is no CSRF
  protection ([0040](0040-google-sign-in-cookie-sessions.md)). A hosted frontend
  should share a site with the API, or add that protection first.

## Consequences
- The service spins down after 15 minutes with no requests, and the next request
  waits for it to start. **That kills a running job**, even one that is still
  working, because only inbound traffic keeps it up. A long backfill needs
  something requesting the API, or a paid plan.
- Startup then fails the interrupted job ([0020](0020-jobs-in-the-api-process.md)),
  so it can be started again from `resume_from`
  ([0022](0022-no-retries-resume-instead.md)).
- Every start checks for migrations, which adds a little to each cold start.
- A migration runs while the previous version is still serving, so it has to
  keep working for that version.
- There is no shell on the free plan. Operator commands
  ([0036](0036-operator-commands-in-cli.md)) run from a laptop with the Neon URLs
  in `.env`.
- Training on a free instance hasn't been tried. Until it has, train from a
  laptop against Neon (`just dev --neon`).
- Render's free plan has no cron jobs, so scheduling needs its own decision.
